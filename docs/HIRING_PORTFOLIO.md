# How to use Checkmate in quant / fintech interviews

## Accurate positioning

Independent creator of a rules-driven MNQ futures research system using historical one-minute market data. Built a versioned, test-oriented research workflow to evaluate scenario sensitivity, exit timing, risk controls, and TradingView-exported performance. Implemented a public-safe Python reporting toolkit and a reproducibility protocol. Broker-tracked observation remains early-stage (~one month or less); simulated results are not live audited returns.

## Demonstrated engineering skills

- Python CLI, typed structures, Decimal arithmetic, CSV data parsing, SHA-256 audit trails.
- Automated tests, GitHub Actions CI, scenario comparisons and evidence provenance.
- Data integrity and reproducibility methodology, backtest-vs-live distinctions.
- Program thinking: bounded scope, immutable controls, escalation criteria, incremental gates.

## Next artifacts that will add interview value

- Trade event schema and validated broker fill reconciliation (**with fake data**).
- Market-data integrity checks (timezone, exchange calendar, roll mapping).
- Walk-forward validation notebook with clear train/test boundaries.
- FIX message-flow diagrams and incident handling runbooks.

## Claims to avoid

Never imply proprietary strategy source is public, a backtested P&L is broker-verified live income, sample tests validate trading edge, or this package is a production trading service.
